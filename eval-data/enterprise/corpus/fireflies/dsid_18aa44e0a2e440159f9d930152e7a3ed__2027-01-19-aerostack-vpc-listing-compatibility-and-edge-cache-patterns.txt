[11:10] Marcus Li: About the edge cache pattern you mentioned — we have heavy inter-region egress costs when embedding generation returns large token counts. what is the recommended approach?
[12:00] Samir Rao: Two patterns: 1) prefix/KV cache inside the VPC close to the model runtime — Redwood's runtime supports automatic KV cache for previous prefixes (doc says KV cache) which reduces repeated attention recompute. 2) a lightweight external edge cache (Redis/ElastiCache or CDN) that stores short-lived generation prefixes. the tradeoff: internal KV gives lowest latency but uses GPU memory; external cache reduces GPU work but adds network hops.
